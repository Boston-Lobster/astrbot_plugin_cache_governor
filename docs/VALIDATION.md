# 验证记录与统计边界

## v0.1.0

验证日期：2026-10-25。接口集成验证环境为 AstrBot 4.29.1 / Python 3.14；纯逻辑测试无第三方依赖。

14 项纯逻辑测试覆盖：背景子段内容保留、未知或歧义结构回退、稳定前缀比较、消息与工具边界、临时标记、幂等、关闭规则、工具复制、作用域隔离、指纹淘汰、usage 兼容、零用量处理、数值日志隐私、轮转、并发和存储失败隔离。

实际 AstrBot 接口测试使用 ProviderRequest、ToolSet 和 bind_checkpoint_messages，验证了：

- 本轮 prompt、system、附件及原始工具链保留。
- 临时背景的 `_no_save` 标记保留，历史保存过滤后不包含合成记忆。
- 工具执行入口保留，排序不修改原工具列表。
- 禁用时保持请求原样。
- 重载与终止只移除自身路由，不删除后加载实例的路由。

测试事件、消息和记忆均为合成数据，没有向真实联系人或群发送消息。这些测试不等于所有第三方插件或真实聊天行为均已通过验收。

## 六请求合成 API 对照

通过同一模型适配器，构造相同的合成历史、记忆、情绪、工作状态和本轮消息。每次改变情绪、工作状态、灵魂状态和本轮问题，对比调整前后的背景排列；未删除任何背景或添加无用长提示。

| 布局 | 第一次命中 / 输入 | 第二次命中 / 输入 | 第三次命中 / 输入 |
| --- | ---: | ---: | ---: |
| 当前顺序 | 0 / 1297 | 128 / 1297 | 128 / 1297 |
| 规范顺序 | 128 / 1297 | 1024 / 1297 | 1024 / 1297 |

预热后两次分别约为 9.9% 与 79.0%，未命中输入从 1169 降至 273 token。包含各组三次请求时，命中率分别约为 6.58% 与 55.92%。

规范组首轮已经复用了前组共同的少量历史前缀，因此这不是两个完全独立的冷缓存实验。数值来自服务商原始 DeepSeek usage，是特定短时场景的结果，不是生产流量平均值，也不能据此推断其他模型的收益。实验不需要或公开任何账号、API Key、端点配置、聊天正文或运行日志。

## 如何在自己的环境验证

1. 先核对 AstrBot 版本和插件组合，保存当前配置。
2. 保持相同模型、触发策略和功能，以相近的真实使用场景分别观察规范规则关闭与开启后的统计。
3. 将冷请求与预热后的请求区分，关注总输入、未命中输入、请求数及实际费用。
4. 对背景排序前后的回复行为、工具调用、临时信息保存边界做必要核验。

不要用本插件统计与其他插件的重叠统计相加，也不要把主 agent 最终响应钩子的数据称为整个 API 账户用量。服务商没有返回有效用量时，本插件返回暂无数据；它不能判断失败请求的实际计费。
