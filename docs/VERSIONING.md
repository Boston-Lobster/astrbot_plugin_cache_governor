# 版本隔离策略

## 版本与分支

- `main` 用于后续开发。
- `codex/v0.1-maintenance` 隔离 0.1 系列维护；这里只合入适合该系列的兼容修复与文档更新。
- 每次正式发布建立独立标签，例如 `v0.1.0`，并对应 GitHub Release。
- 已发布标签不移动、删除后重建或强制覆盖。修复内容通过新版本发布。

v0.1.0 的版本声明为 AstrBot `>=4.29.1,<4.30.0`。放宽版本范围前需要验证相应接口；只通过纯逻辑测试不能视为通过新 AstrBot 版本验收。

## 安装包隔离

构建脚本只收录明确列出的运行文件、README、LICENSE 和包内版本清单。测试、开发文档、CI 文件及运行数据不进入插件安装包。

每个 Release 提供：

- `astrbot_plugin_cache_governor-vX.Y.Z.zip`
- `SHA256SUMS`
- `release-manifest.json`：安装包与每个包内文件的 SHA-256

同版本的公开源码和安装包按标签固定。更新 README、元数据或其他包内文件也会影响安装包校验值，应以该 Release 的清单为准。

## 升级与回退

升级前备份自己的插件配置和统计数据，阅读 CHANGELOG 与 AstrBot 版本范围。需要回退时先禁用当前版本，再上传目标 Release 安装包；确认配置兼容后启用。

本插件没有替换其他插件源码或修改聊天数据库的操作。禁用本插件即可停止其规范逻辑，不应通过覆盖整个 AstrBot 数据目录回退。

新增背景注册协议、改变适配语义或跨越 AstrBot 兼容边界时，使用新的次版本并说明迁移要求，不静默替换固定版本。
